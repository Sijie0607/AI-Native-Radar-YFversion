# 雷达历史版本对比｜产品 Brief

## 1. 功能背景

- 当前首页雷达只展示"当前状态"的单一时点：用户能看到的永远是最新雷达，无法知道它如何演化。
- 评分/推荐会实时改变推荐指数与视觉权重（radar-renew.md 已定稿），但"这本书上周在不在雷达上、上周指数多少、这周是涨是跌"没有任何历史痕迹。
- 产品定位强调"动态演化"，雷达的演化过程本身应当可感知。
- 本轮新增"历史版本对比"：以周为版本单位，对比当前版本与上一版本的雷达差异。

## 2. 本轮目标

- 以"周"为版本单位，为雷达生成可对比的历史版本。
- 首页支持"当前 vs 上一版"的对比视图。
- 对比至少覆盖：新增/删除书籍、推荐指数升降、评分/推荐人数变化、视觉权重变化。
- 版本数据落 Supabase，前端只读对比。
- 保持 8 大领域 + 3 层难度结构，不破坏雷达基础语义。

## 3. Scope

### 3.1 本轮要做

- 周版本生成机制：每周 AI 自动审核 → 重算推荐指数 → 高分书进雷达 → 生成版本快照。
- 版本快照后端存储（Supabase 新增表）。
- 首页"当前 vs 上一版"对比视图与对比态渲染。
- 对比维度的视觉表达规则。

### 3.2 本轮不做

- 任意两版对比 / 时间轴回放（本轮只要"当前 vs 上一版"）。
- 账号体系、审核后台（人工审核）。
- 自动收录（外部抓取）。
- 同圈层内重排 / 跨圈层位置变化。
- 版本数据导出。
- 移动端深度适配（延续桌面优先）。

## 4. To-Be Journey

1. 用户浏览首页雷达。
2. 打开版本对比入口（如"本周更新"按钮）。
3. 雷达进入对比态：新增书高亮、删除书留残影、指数涨跌可视化。
4. 用户感知本周雷达演化（新增/删除/涨跌/人数变化）。
5. 关闭对比，回到当前版本视图。

## 5. 已确认事实

### 5.1 版本定义（周更机制）

- 一个版本 = 一次周更后的雷达全量状态。
- 每周生成一次版本（周期 7 天，版本号每周递增）。
- 每周对"本周推荐的新书"和"雷达中已存在的书"重新计算推荐指数。
- 推荐指数高的书放入雷达，更新雷达。

### 5.2 周更即 AI 自动审核

- 每周的推荐指数重新计算本身就是一种审核机制。
- 该审核不是人工审核，而是 AI 自动审核。
- 高分新书进入雷达，低分新书保持 pending。
- "新书进雷达"不等于无门槛自动上架，而是通过 AI 审核的质量门槛后进入。

### 5.3 进雷达判定（"推荐指数高"的量化）

- 需**同时满足**以下两个条件才进入雷达：
  1. 每领域推荐指数排名前 Top 8（沿用前端 `MAX_RADAR_POINTS_PER_DOMAIN = 8`）；
  2. 推荐指数 ≥ 3.0（与现有"最低 3 星起评"一致）。
- 不满足任一条件则不进入雷达：新书保持 pending，现有书 `radar_visible = false`。

### 5.4 对比方式

- 当前版本 vs 上一版本。

### 5.5 对比维度

- 新增书籍：本版有、上版无。
- 删除书籍：上版有、本版无。
- 推荐指数升降：两版都有，分数变化。
- 评分/推荐人数变化：votesCount 增减。
- 视觉权重变化：由指数变化驱动的点大小/光晕/描边/颜色强度变化。

### 5.6 数据存储

- 版本数据存 Supabase 后端，前端只读对比。
- 旧版本可清理（保留周期待定）。

### 5.7 结构语义（沿用）

- 扇区 = 领域、圈层 = 难度，不变。
- 推荐指数不改变圈层归属（沿用 radar-renew.md 规则）。

## 6. 与现有产品的关系

### 6.1 不冲突的部分

- radar-renew.md 定稿的视觉权重模型（point_radius / halo / stroke / fill_opacity）直接作为对比表达的视觉基础。
- `radar_display_state` 已记录的 `update_type` / `score_delta` / `recently_updated_at` 可作为版本内变化线索。
- `refresh_resource_metrics` 就是"推荐指数重算"逻辑，周更直接复用。
- 已存在的 `ai_evaluations` 表（领域/难度建议、质量分、置信度、质量信号）可作为 AI 自动审核结果的落点。

### 6.2 本轮新增的能力

- 版本概念与版本存储。
- 周更的"AI 自动审核 + 雷达成员更新"（高分进、出局留痕）。
- 首页对比视图。

### 6.3 与"雷达自动更新"的关系

- 雷达自动更新（radar-renew）解决"评分后视觉权重立即变"，是**实时层**。
- 历史版本对比解决"每周雷达成员与分数的演化"，是**版本层**。
- 两者并存：实时层影响当前视图；版本层以周为粒度沉淀快照，供对比。
- 实时层与版本层的优先级关系：**未定（待确认）**。

## 7. Journey 断点判断

### 7.1 当前雷达无历史概念

- 只有当前状态，无版本，无对比。

### 7.2 当前雷达成员规则是"发布即上架"

- `radar_books` 视图以 `status = 'published'` 为准，没有周更门槛，也没有 AI 审核环节。

### 7.3 当前无版本存储

- 无版本表、无版本查询。

### 7.4 当前无对比表达

- 雷达只能表达当前态，无变化态。

## 8. 进入 UI 设计前的固定业务规则

### 8.1 版本生成（周更）规则

1. 每周生成一次版本（定时触发，周期 = 7 天）。
2. 周更流程 = AI 自动审核 + 重算：
   - 对本周推荐的新书做 AI 审核，产出/校准其推荐指数；
   - 对雷达现有书重新计算推荐指数（复用聚合逻辑，可选 AI 校准）。
3. 进雷达判定：**同时满足**"每领域 Top 8"且"推荐指数 ≥ 3.0"，否则不进雷达。
   - 高分新书 → 进入雷达（`radar_visible = true`，分配点位与视觉权重）。
   - 低分新书 → 保持 pending，不进入雷达。
   - 现书不满足 → `radar_visible = false`，在对比中标记为"删除"。
   - 被删除的书后续若重新满足条件，可重新进入雷达（对比中再次标记"新增"）。
4. 生成版本快照并落库，版本号 +1。
5. 可清理过旧版本（保留周期待定）。

### 8.2 对比判定规则

- 新增 = 本版有、上版无。
- 删除 = 上版有、本版无。
- 指数升/降 = 两版都有，score 差值。
- 人数变化 = votesCount 差值。
- 视觉权重变化 = 指数变化驱动的 point_radius / halo / stroke / fill 差值。

### 8.3 对比展示规则（建议）

- 新增：正常点位 + "新增"标记（亮色光晕/徽标）。
- 删除：残影/置灰呈现，保留上一版信息但不再占雷达点位。
- 指数升：视觉权重增强（主表达沿用点大小）。
- 指数降：视觉权重减弱。
- 状态优先级：对比态不破坏 hover / 选中（沿用 radar-renew 的优先级思想：selected > hover > 对比态 > 默认）。

## 9. 已知事实 / 设计建议 / 待确认假设

### 已知事实（已确认）

- 版本机制：每周一个版本，每周生成一次。
- 进雷达判定：每领域 Top 8 且推荐指数 ≥ 3.0，同时满足。
- 周更 = AI 自动审核（非人工），高分新书进雷达、低分新书 pending。
- 存储：Supabase 后端，前端只读。
- 对比方式：当前 vs 上一版。
- 对比维度：新增/删除、指数升降、评分/推荐人数变化、视觉权重变化。
- 旧版本可清理。

### 设计建议

- 版本生成用定时触发（每周一次）。
- AI 审核结果写入现有 `ai_evaluations` 表，与周更函数联动。
- 对比视图用"叠加/高亮"而非重排，不破坏结构。
- 删除的书保留残影但不占雷达点位。

### 待确认假设

- 实时层（radar-renew）与版本层（本轮）的优先级关系：未定。
- AI 审核如何产出推荐指数：AI 直接为低票数新书评分，还是 AI 校准用户投票聚合值？需明确。
- 版本保留周期：可清理，具体保留几版/多久待定。
- AI 审核的落地方式：Edge Function 调 LLM？还是先以规则/人工占位？待定。

## 10. 数据与实现约束

### 10.1 现有代码基线

- `radar_display_state` 已有 update_type / score_delta / recently_updated_at / 视觉权重字段。
- `refresh_resource_metrics` 提供推荐指数重算。
- 前端 `MAX_RADAR_POINTS_PER_DOMAIN = 8` 已限制每领域点位。
- `radar_books` 视图是前端 Book 数据源。
- `ai_evaluations` 表已存在，但当前无流程写入。

### 10.2 后端新增（建议）

- 表：`radar_versions`（版本元数据：版本号、周区间、生成时间）、`radar_version_books`（版本内每本书快照：score / votesCount / 坐标 / 视觉权重）。
- 函数：`generate_weekly_version()`（AI 审核 → 重算 → 定成员 → 写快照 → 更新 radar_display_state）、`get_version_diff()`（返回当前 vs 上一版 diff）。
- 关联：复用/扩展现有 `ai_evaluations` 表作为 AI 审核结果落点。
- 数据原则：版本只读，不写回 Book，不改变现有表结构语义。

### 10.3 前端新增（建议）

- 版本对比类型（versionDiff：added / removed / scoreUp / scoreDown / changed）。
- 首页对比入口 + 对比态渲染（RadarChart 增加对比层 props）。
- 加载对比数据的 service（复用 backendClient）。

### 10.4 组件影响范围

- 核心改动：RadarChart（对比渲染层）、Home（入口/状态）、版本对比 service。
- 不应改动：点位分布算法、领域/难度结构、评分/推荐业务规则。

## 11. 改变 / 不变 / 复用 / 不做

### 改变

- 雷达从"单时点视图"变为"可对比的历史视图"。
- 首页新增版本对比入口与对比态。
- 雷达成员从"发布即上架"变为"周更 AI 审核 + 高分进雷达"。

### 不变

- 8 大领域、3 层难度、扇区/圈层语义。
- 推荐指数不改变圈层归属。
- 雷达点位分布算法。

### 复用

- 视觉权重模型（radar-renew.md）。
- `refresh_resource_metrics` 重算逻辑。
- `radar_display_state` 字段。
- `radar_books` 数据源与 bookMapper。
- `ai_evaluations` 表结构。

### 不做

- 任意两版对比 / 时间轴。
- 账号体系 / 人工审核后台 / 自动收录。
- 圈内重排 / 跨圈层位置变化。

## 12. 一句话基线

本轮历史版本对比的定位是：以周为版本单位，每周由 AI 自动审核本周新书并重算雷达现有书推荐指数，将同时满足"每领域 Top 8"且"推荐指数 ≥ 3.0"的高分书放入雷达，其余低分新书保持 pending，并把每次周更后的雷达状态沉淀为 Supabase 中的版本快照；首页提供"当前 vs 上一版"对比视图，通过新增/删除、推荐指数升降、评分人数与视觉权重变化，让用户直接感知雷达的动态演化，但不改变 8 大领域与难度结构。

## 13. 风险与最小验收标准

### 风险

- 周更成员更新可能带来"书突然消失/出现"的困惑 → 删除需保留残影与说明。
- AI 自动审核的质量不确定性 → 需有质量信号与兜底（沿用 `ai_evaluations` 的质量字段）。
- 版本生成时机依赖（定时任务未跑/失败时对比数据缺失）。
- 新书进雷达与现有 pending 流程的衔接需清晰（低分不误入）。
- 视觉表达过强破坏雷达秩序（沿用 radar-renew 约束）。

### 最小可用版本验收标准

- 每周版本可生成并落库。
- 首页可对比当前 vs 上一版。
- 对比至少覆盖：新增/删除、指数升降、人数变化、视觉权重变化。
- 对比不改变扇区/圈层归属。
- hover / 选中仍正常。
- 对比入口有明确语义提示（如"本周更新"）。
