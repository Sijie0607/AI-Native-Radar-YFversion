第四幕 · 现场演示

三条用户路径，跑起来

🧭 路径 A · 定向学习某个领域

  • 进入 /list，按领域 / 难度 / 推荐指数筛选
  • 打开领域学习路径，查看入门 → 方法 → 进阶
  • 点击书籍进入 /detail/:id，判断是否适合当前阶段

🌱 路径 B · 推荐自己读过的好书

  • 从导航栏或首页入口打开书籍推荐抽屉
  • 填写书名、作者、所属领域、推荐理由和推荐指数
  • 提交后获得成功 / 重复 / 失败反馈，并保留本次会话记录

🎬 路径 C · 探索书籍和领域

  • 进入首页 /，先看 8 领域 × 3 难度的雷达全貌
  • 悬停点位或书名纸片，查看推荐指数与推荐理由
  • 点击打开详情侧栏，也可进入列表页继续探索热门 / 上新 / 路径
定向学习 · 参与共建 · 探索发现 —— 三种目的，对应三条完整路径
第五幕 · Vibe Coding 之旅

从 0 到 1，搭起稳定可用的核心功能

这不是一个大团队做的——是我在 AI 产品经理培训中的 Vibe Coding 实践里，用 Trae + Codex 与 AI 结对做出的原型。

💡 MVP 构建心得

构建 MVP 产品时，最重要的是先把核心功能模块做成一条稳定可用、能跑通完整用户旅程的路径。若一开始就陷入过细的问题和局部功能细节，很容易被某个点卡住，造成后续迭代时间被打乱、构建过程变混乱。因此，在开工前要先定义清楚：本期 user journey 要实现到哪里结束，哪些能力必须覆盖，哪些内容明确不在本期完成。

第六幕 · 协作与打磨

印象最深的两件事

🤝 协作：Git 仓库

  • 小组项目，从不会用 GitHub 到离不开
  • 建项目仓库、推代码、拉别人的代码
  • 仓库保留原型每个版本，方便随时回溯
  • 踩坑：拉取后原型没更新 → 请对方重传才成功（猜测首次上传不完整）

✨ 打磨：UI 细节

  • 站在用户角度，审视视觉 UI 与交互体验
  • 越改发现问题越多，磨人但值得
  • 是产品真正上线前必不可少的打磨过程
  • 没有完美产品，只有一遍遍迭代，更接近理想
而正因一步步做出来，我也比谁都清楚它的不足——
第六幕 · 协作与打磨

诚实地看不足

📊

数据质量 最优先

当前是示例书库 + 社区投票的「起点」；真实上线需权威推荐人、更多投票与防刷 & 质量分机制。

🕳️

冷启动

新领域 / 新书无人投票，需要「种子推荐人」与平台引导机制。

🛡️

内容治理

推荐理由与评分的质量，需要规则 + 人工双通道审核。

🧠

推荐深度

目前是「均值指数 + 每周 Top 8」；长期可加入同领域进阶、基于学习记录的个性化。

这些不足，不是终点，而是下一轮「共建与演化」的起点。
